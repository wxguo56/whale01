# 代号鲸鱼01：三套 UI 与动效系统设计方案

版本：v0.1｜日期：2026-11-09｜目的：供负责人选择一套完整体验方向，再由执行者实现。

本轮包含三个可交互概念方案、五个页面／状态的布局、视觉与字体规范、动效状态机、陪伴玩法、音乐体验、无障碍与原生交付要求。不是只给原有界面换三种颜色。

概念预览中的角色、曲目、任务和音效状态均为设计示例。没有调用模型、系统服务或播放真实音频；也不是香蕉生成图片。香蕉连接后按选中方案制作正式角色与场景素材。未选中的方案保留为设计备选，不要求执行者开发三套原生 App。

## 1. 三套方向对比

| 维度 | 汐屿：清新陪伴 | 星潮：柔和科技 | 回声：温暖音乐小馆 |
|---|---|---|---|
| 第一感受 | 像走进一座安静的小岛 | 像唤醒一个可亲近的智慧空间 | 像坐进一家熟悉的小馆 |
| 首页结构 | 场景与角色优先，生活工具收在次级入口 | 光核与环绕能力入口，任务状态更显眼 | 音乐与今日话题优先，角色在旁陪伴 |
| 角色表现 | 轻浮、回头、点头、触碰水纹 | 光核聚合、光环回应、状态共振 | 轻点头、唱片与短笺互动 |
| 对话形式 | 清楚的日记式对话，少边框 | 模块化信息与执行轨迹，正文保持普通中文 | 温暖信件／便笺式对话 |
| 音乐形式 | 水面封面、轻量控制、安静迷你条 | 光谱封面、队列与状态联动 | 唱片封面、唱针与有节奏的切歌 |
| 互动节奏 | 240–420ms，轻柔、有停顿 | 160–300ms，清楚、利落 | 220–450ms，温暖、略带触感 |
| 长时玩法 | 换小岛光景、留一句话、安静陪伴 | 光核回应、专注舱、可回看的信号卡 | 听歌聊感受、今日话题、回声短笺 |
| 首版实现重点 | 场景分层、角色姿态与舒适排版 | 状态映射、光效层级与执行反馈 | 音乐协调器、卡片编排与声音控制 |

建议按产品核心选择：角色陪伴优先选汐屿；科技辨识度优先选星潮；音乐与聊天停留优先选回声。三套共享同一 Agent 和工具，不改变 DeepSeek／讯飞的选型。

## 2. 全局共同规范

### 信息架构

四个一级区域：主场景、对话、音乐、我的。分别叫“岛屿／空间／小馆”，其余区域名称一致。S03 操作确认采用 sheet，不占一级入口。

保留 S01 首页、S02 对话、S03 确认、S04 我的／设置、S05 音乐。明确的历史返回／前进与左滑返回、右滑前进共存；输入、竖向阅读、横向列表和音乐进度条优先处理自己的手势。

### 文字与颜色

正文基准 16–17pt、行高约 1.5–1.6；标题 26–32pt；辅助文案 13pt 左右；关键操作不用小字号。原生最终以系统 Dynamic Type 样式为准，不把像素字号写死。

每屏优先一个明确主动作。角色、封面和装饰不遮挡正文。长回复分段，任务卡展示参数，聊天只补充意图和下一步。

普通正文与背景对比度目标至少 4.5:1；焦点、按钮和状态同时有形状／文字提示。颜色 Token 随明暗主题切换，不能把整屏彩色背景当作长篇阅读底色。

点击有效区域约 44×44pt 起。按钮按下时缩放控制在约 0.98～0.99，不让控件大幅弹跳或移开手指位置。

### 长时间使用节奏

陪伴内容可进入、可暂停、可结束；聊天、音乐、光景与个人短笺组成可选活动。没有不断弹出的催促、随机权限索取或强制每日任务。

输入和阅读时减少角色动作；进入背景、隐藏页面或降低动态效果时停止无必要动画。音乐播放由独立协调器管理，切页不重启队列。

声音默认不自动播放。微交互提示音独立开关，默认关闭；音乐与语音有清楚的控制。触感只用于用户动作、明确状态变化和重要结果，不给每段文本振动。

## 3. 方案：汐屿

### 品牌与视觉

关键词：海盐、薄荷、晨雾、柔光、陪伴。自然的浅色表面、深青绿文字和少量暖阳色。角色像在小岛附近浮游，形体柔和，表情克制。

| Token | 浅色 | 深色 |
|---|---|---|
| background | #F2F8F2 | #101F19 |
| surface | #FFFEF8 | #1C3027 |
| textPrimary | #203B32 | #E8F3EB |
| textSecondary | #586E61 | #AAC1B2 |
| accent | #226C59 | #82CDAA |
| onAccent | #FFFFFF | #102B1E |
| softAccent | #DDEDE3 | #294A3C |

卡片圆角约 22–26pt；区块间距 20–24pt。白色卡片不是铺满一屏，首页主体保留场景感，阅读页回到稳定表面。

### 五页布局

- S01：一句问候 → 岛屿与鲸鱼场景 → “和鲸鱼聊聊”主动作 → “听一会／记件小事” → 可展开的生活助手入口。
- S02：紧凑角色头像与状态 → 日记式消息 → 轻任务卡 → 固定可触达的文字／语音输入。长文本不叠彩色边框。
- S03：奶油色 sheet，标题、事项、时间与时区清楚排列，绿色确认按钮，取消为次级动作。
- S04：阅读、动效、语音和权限分组；所有权限独立展示。
- S05：柔和水面封面、曲名、播放控制、候选队列。其他页迷你播放器像一条小浮标，不遮挡输入。

### 动效系统

| 触发 | 表现 | 初始参数 |
|---|---|---|
| 轻触角色 | 鲸鱼轻浮、回头，出现一次水纹 | 560ms，位移约 4–6pt |
| 开始倾听 | 光景安静下来，角色面向用户 | 280ms，随后随实际状态保持 |
| 模型理解中 | 一次柔光聚合，显示“正在理解” | 360ms，等待期间不重复晃动 |
| 待用户补充 | 角色静止，突出问题与选项 | 220ms |
| 打开确认 | sheet 从下方进入，背景轻收暗 | 320ms，ease-out |
| 已完成 | 一次轻点头及明确状态文字 | 420ms，原生 success 触感一次 |
| 失败或未知 | 收起装饰、展示可行下一步 | 220ms，不用悲伤表情施压 |

### 可玩与停留

“换个光景”：用户主动选择晴空／雨雾／夕光，只是场景主题，不假装代表真实天气。“留一句今天的话”：明确操作后保存短笺，之后可再打开。安静陪伴模式让角色在音乐旁存在，阅读时保持安静。

首版可做光景切换和一次触碰回应；个人短笺存储、跨日回看作为新增功能单独接入，不能靠视觉稿标为已经完成。

## 4. 方案：星潮

### 品牌与视觉

关键词：深空、信号、光核、秩序、可亲近。主色为淡紫与深靛，光只集中在角色和交互焦点；正文仍用稳定、不发光的文字。

| Token | 浅色 | 深色 |
|---|---|---|
| background | #F2F0F8 | #101525 |
| surface | #FCFAFF | #1C2338 |
| textPrimary | #292940 | #ECEDF9 |
| textSecondary | #65627C | #B1B5CF |
| accent | #6753AD | #B9A7F5 |
| onAccent | #FFFFFF | #201638 |
| softAccent | #E9E3F7 | #342C52 |

卡片圆角约 16–20pt；光效区域与阅读区域分离。首版用轻量分层和合成动画即可，重实时 3D 不是前置条件。

### 五页布局

- S01：简短标题 → 中央光核 → 天气／日程／音乐／提醒围绕光核的直接入口 → 一条说话／输入入口 → 当前待办。
- S02：自然消息与模块化任务卡，执行步骤显示“待核对／已确认／处理中／已完成”等可观察状态，不展示模型内部分析。
- S03：参数核对面板，事项、时间、时区为独立可读字段；一层确认，背景光核减亮。
- S04：舒适显示与独立权限列表；专注舱只是 App 内模式，不能暗示已修改系统勿扰。
- S05：光谱封面、曲目和状态、队列；播放／暂停／切歌控制清楚，进度操作不触发页面历史。

### 动效系统

| 触发 | 表现 | 初始参数 |
|---|---|---|
| 触碰光核 | 一次光环向外扩展，核心轻缩再回位 | 480ms |
| 开始倾听 | 环绕入口降低强调，音量线只随实际输入 | 180ms；采集权限未授予时不显示已收音 |
| 理解中 | 光点聚成中心、简短状态明确 | 260ms |
| 工具选择／执行 | 对应能力入口及任务卡被点亮 | 180–220ms，只反映真实事件 |
| 等待确认 | 动效停下，聚焦核对面板 | 200ms |
| 已完成 | 一条光迹收束为状态标记 | 320ms，单次触感 |
| 切换页面 | 方向明确的短距离移动 | 200–240ms，不把阅读内容旋转飞走 |

### 可玩与停留

光核触碰是即时回应，不要求任务才能互动。“专注舱”让音乐和极简角色占主位，用户可随时退出。“信号卡”将用户明确选择保留的对话片段做成可回看的卡片，不能默认存整个聊天。

科技感来自空间与状态关联。避免长时间高亮、闪烁或与执行无关的进度百分比。首版没有真实语音时，“倾听体验”只演示动画并明确标为预览。

## 5. 方案：回声

### 品牌与视觉

关键词：唱片、纸张、暖光、手感、故事。奶油白、陶土色与深咖文字，正文保持清楚的系统字体；标题可略有编辑感，但不让中文长篇正文使用难读的装饰字体。

| Token | 浅色 | 深色 |
|---|---|---|
| background | #FAF4EB | #241D19 |
| surface | #FFFDF8 | #362B24 |
| textPrimary | #49362B | #F6EDE4 |
| textSecondary | #786152 | #CDB9A9 |
| accent | #9F4A31 | #E8AA8A |
| onAccent | #FFFFFF | #321C13 |
| softAccent | #F3E4D4 | #50392B |

卡片圆角约 12–16pt，有较明显的版式和轻触感；不做仿真皮革、复杂纹理和难读的旧纸噪声。

### 五页布局

- S01：编辑式标题 → 小馆唱片／角色场景 → “一起听一会” → 今日话题 → “聊聊／记件事／生活助手”。
- S02：便笺式对话和清楚的发送者分隔，任务像一张待核对短笺；长读时装饰减少。
- S03：短笺展开成确认 sheet，真实字段和操作一目了然，不借装饰隐藏取消按钮。
- S04：语音、动效、音乐、独立授权和个人短笺管理。
- S05：唱片主视觉、曲名与艺人、播放／切歌、进度、音乐库；其他页保留安静的迷你播放条。

### 动效系统

| 触发 | 表现 | 初始参数 |
|---|---|---|
| 轻触唱片／角色 | 一次轻摆、唱针回应 | 520ms |
| 播放 | 唱片缓慢旋转，暂停时平稳停下 | 约 24–30s 一圈，仅当前可见播放区域 |
| 切歌 | 封面短距离滑动，标签同步更新 | 280–340ms |
| 发送消息 | 短笺轻落位，不逐字抖动 | 220ms |
| 查看确认 | 短笺展开，背景减弱 | 300ms |
| 已完成 | 一次轻盖章式状态切换 | 380ms，不发强烈默认音效 |
| 阅读或键盘输入 | 角色与唱片装饰减少运动 | 按状态停止，无额外强制等待 |

### 可玩与停留

“今日话题”是一个可进入的聊天起点，不是不断刷新的信息流。“回声短笺”让用户保留想留住的一句话；音乐页提供“想聊聊这首吗”的入口，依据真实曲目资料与用户意愿展开聊天，不擅自判断情绪或记录画像。

首版可以做音乐与对话联动入口、一次触碰反馈。真实曲库、音频、歌词／资料、短笺持久化各自完成接入后才展示相应可用状态。

## 6. 共用动效状态机

| 状态 | 真实触发来源 | 共同行为 |
|---|---|---|
| idle | 没有活动输入或执行 | 稳定可操作；无必要连续动画 |
| listening | 实际录音开始 | 显示收音与停止；不会因动画而自动申请麦克风 |
| thinking | 实际模型请求开始 | 短过渡后保持稳定，不假装显示内部推理 |
| responding | 实际讯飞 TTS 播放开始／结束 | 轻回应或近似口型随真实音频驱动，打断后停止 |
| waiting_user | 缺字段、选择或确认 | 停止环境干扰，突出可操作控件 |
| executing | 原生／服务工具开始 | 当前步骤清楚，允许停止尚未开始的后续动作 |
| completed | 可信成功结果 | 单次完成反馈，状态文字同步 |
| handoff | opened_external_app | 只表达已交接 |
| failed／unknown | 错误或结果待核对 | 说明原因与下一步，不播放成功动作 |
| cancelled | 用户取消 | 不重启旧动画或旧操作 |

动效由统一 MotionCoordinator 驱动；业务状态与皮肤分离。停止、确认、权限与幂等仍由现有 Agent／执行层校验，外观不能扩大系统权限。

任务、语音与音乐是三个独立状态层：停止播报不等于撤销已完成任务，切页不等于停止音乐。角色状态由优先级导出，等待用户核对和错误说明优先于装饰反馈，用户开始说话时停止旧播报及其动画。

讯飞产品没有提供音素／口型对齐数据时，可用实际音频包络做近似嘴型或光效，不能承诺精确口型同步。三套不同语气共享同一真实语义 Agent；角色表现不替代 10_自然对话与Agent升级方案.md 的模型与上下文改造。

## 7. 持续动画与舒适开关

原生采用统一的“标准／安静”动效偏好并服从系统 Reduce Motion。降低动态效果时用静态状态、轻量透明度变化和文字替代位移，不取消操作反馈。

环境动画仅在可见、前台且用户需要时运行；静置后收敛。唱片旋转只在播放且所在可见区域有效时运行；音乐后台继续播放不要求后台渲染唱片。

阅读正文 16～17pt，用户可以切大字。放大字体后布局增高而不是缩字，按钮与输入仍可触达。深色表面保留足够文字对比度，光效在视野中面积有限。

所有触感与短提示音由事件合并与限频，避免流式 token、音频分片或重复事件触发一串振动。默认不自动播提示音。

## 8. 手势与状态保留

按负责人已有要求：左滑返回、右滑前进。对进入新一级页、返回历史与 sheet 采用不同动画；前进历史可用性不靠动画猜测。

输入编辑、文本选择、横向组件、进度拖动、系统／确认弹层及竖向滚动优先。避免与 iOS 系统边缘返回同时识别。返回保留消息、输入、任务和选曲，不重复执行工具；音乐不因切页暂停。

确认 sheet 有明确取消与关闭。减少动态效果、VoiceOver 和键盘用户能用按钮完成同样流程。

## 9. 原生实现与资产交付

复用现有业务逻辑和 10_自然对话与Agent升级方案.md 的真实模型改造。选定一套视觉后再实施原生，不将三个原型都做成三份重复业务代码。

建议交付：

- 一套选定主题的语义颜色、字体、间距、圆角与动效 Token。
- 五页明暗设计、关键空态／权限／失败／未知结果状态。
- 角色六姿态或分层资产：待命、倾听、理解、回应、完成、失败；口型／声音响应由真实音频驱动。
- 场景背景与可选光景素材；真实音乐封面或明确占位规则。
- 可取消的动画事件映射、减少动态效果替代、触感／声音策略。
- 真机 UI 与设计对照、动态字体／VoiceOver／键盘／手势／耗电检查。

轻量首版可用 SwiftUI、Core Animation 或已选动画资源；不先引入重 3D／粒子框架。真实 API、音源、素材权利及系统权限按各自任务完成。

## 11. 体验验证与选择方法

用同样的任务比较三套方案：从首页进入对话、看提醒确认、选歌、切页看迷你播放器、体验角色回应、打开大字／减少动效。

选择时观察：是否一眼看懂下一步；是否愿意看一段较长文字；互动是否轻而明确；角色是否让人想再碰一下；音乐与对话是否互相打断；小屏、深色和安静模式是否仍完整。

长时间体验需实际用户与真机验证。本方案不承诺提升具体停留时长、留存率或耗电数值；这些需要选择方案并接入真实系统后测量。

## 12. 本轮交付与下一步

当前交互预览提供三种布局、角色／场景触碰反馈、五个页面／状态、音乐模拟、确认与历史导航。状态皆为 UI 概念演示，不发声、不读取手机数据。

选择一套后，大脑冻结主题和交互节奏；执行者按素材清单调用香蕉细化，再还原原生页面，并继续真实模型与工具接入。其余两套作为探索备选，后续可复用单个组件，但不混拼三套视觉。

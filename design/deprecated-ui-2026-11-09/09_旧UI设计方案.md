# 代号鲸鱼01：UI 设计方案

版本：v0.1｜日期：2026-11-09｜定位：可评审的布局与交互提案，供原生实现和丹青约香蕉视觉细化

## 1. 推荐方向

推荐「潮汐·陪伴型」：以鲸鱼角色、自然对话和明确任务反馈为主，音乐是可随时进入的常用能力。角色有存在感但不占据整个屏幕。

备选「航线·任务型」：缩小角色区，把未完成任务和快捷操作放在首页前部，适合更强调效率的用户。两套方案共享页面、状态和基础组件，差异在信息布局，而非仅换颜色。

当前已有一份可点击的布局预览，不是香蕉生成图片，也不是运行中的 iPhone App。香蕉生图入口仍待连接；后续按本方案及 07_丹青约香蕉UI设计任务书.md 细化角色、插画和页面视觉。

## 2. 信息架构

一级导航：**首页／对话／音乐／我的**。设置归入“我的”。操作确认作为 sheet，不占一级导航。

保留 S01 首页、S02 对话、S03 操作确认、S04 设置、S05 音乐的现有编号，避免执行任务对不上设计页。

顶部保留明确的历史返回／前进入口，与用户指定的左滑返回、右滑前进对应；没有历史时禁用。一级页面切换和历史移动不重复执行 Agent 工具。

## 3. S01：首页

潮汐布局：紧凑品牌区 → 问候 → 适量角色 → 对话入口 → 天气／日程／运动摘要 → 四个常用操作。四个常用操作为设置提醒、我想听歌、附近地点、查看日程。

航线布局：紧凑品牌区 → 今日操作标题 → 待继续任务 → 对话入口 → 摘要 → 常用操作。首页不放大面积角色展示。

摘要数据必须与对话和设置使用同一来源；没有数据、未授权、读取失败和加载中分别表达。本设计预览只展示摘要入口，不编造真实统计。

## 4. S02：对话与执行

使用清楚的消息气泡和结构化任务卡。用户表达与系统执行结果区分展示。任务卡至少显示动作、主要参数、任务状态及当前可操作按钮。

状态文案：等待补充、等待确认、正在执行、已完成、已交接、部分完成、失败、已取消。补参数期间保留待办任务，用户只回答时间也能继续。

输入区域支持文字、语音入口和发送。键盘出现时输入区跟随安全区上移；角色缩为头像，不挤占正文。未发送输入、历史消息和待确认操作在切页后保留。

## 5. S03：操作确认

采用原生 sheet：标题、执行前状态、可编辑的重要字段、准确时间／时区、主要与次要操作。

创建提醒：事项、时间、时区、列表。主要按钮“确认创建”，次要按钮“取消”。时间有修改入口，修改后旧确认失效。

导航：地点、交通方式，按钮“打开地图”；不复用“尚未写入”的日程文案，也不堆叠多层相同确认。

确认动作绑定具体参数和操作身份；关闭 sheet 不等于创建成功。实际权限弹窗由系统提供，设计稿不能假造授权成功。

## 6. S05：音乐

页面上部是曲目、封面、状态与播放控制，下部是音乐库候选。首次未授权展示授权入口；空库展示空状态；找到同名歌曲让用户选择。

显示播放／暂停、上一首／下一首和进度控件。状态来自实际播放器，按钮点击不等于已经播放。预览里的曲名、封面和进度均为占位，操作不发声。

播放开始后在其他一级页面显示迷你播放器：曲名、播放状态、暂停／继续按钮；点击进入完整音乐页。播放器独立于路由，离开音乐页不停止音乐。

布局预览使用循环的三个示例候选演示切歌；真实播放器必须按实际队列边界处理，循环规则由产品另行明确，不照抄预览行为。

## 7. S04：我的与设置

分组：能力与授权、语音与偏好、数据说明和页面手势。

日历读取、日历写入、提醒事项、运动、音乐、定位各自显示状态，不能以提醒授权推导日历权限。只有当前需要的能力才申请授权。

面向用户不展示工具 JSON、模型内部分析、operationId 或调试日志。开发诊断采用独立入口，仅在开发构建中提供。

## 8. 视觉规范建议

以下是提案初始 Token，待选定方案和香蕉视觉细化后冻结。最终采用语义颜色，随系统切换明暗模式，不在业务代码散落色值。

| Token | 浅色建议 | 深色建议 | 用途 |
|---|---|---|---|
| background | #F6F8FC | #101722 | 页面底色 |
| surface | #FFFFFF | #1A2533 | 卡片、sheet、输入 |
| textPrimary | #162439 | #EDF3FF | 正文、标题 |
| textSecondary | #65748B | #A6B4CA | 描述、辅助说明 |
| border | #E4EAF2 | #2C3A4D | 分隔与轻边界 |
| accent | #286DE4 | 按对比度检查后确定 | 主要操作、选中项 |
| softAccent | #EDF4FF | #1A3151 | 轻强调底色 |

原生排版以系统字体和动态文本样式为基础：页面标题约 25～28pt，正文约 15～17pt，辅助说明约 12～13pt，按钮文字约 15～17pt。这些是基准，不能固定小字号阻止用户放大。

页面水平间距 16～20pt，区块间距 16～24pt，元素间距 8～12pt。普通卡片圆角 16～20pt，确认 sheet 由原生系统呈现。避免多层玻璃、重阴影和所有按钮都高亮。

有效点击区域至少约 44×44pt；底部导航每个目标不小于该范围。SF Symbols 映射：home、message、music、person、bell、calendar、location 等，以实际系统版本支持的符号为准。

鲸鱼角色目前为布局占位，既有角色优先；香蕉素材需要单独交付及用途检查。音乐封面使用真实授权封面或清楚的占位，不能凭设计稿冒充用户歌曲封面。

## 9. 手势与无障碍

按已定规则左滑返回、右滑前进；必须避免与 iOS 系统边缘返回同时识别。输入框、文本选择、音乐进度、横向列表及弹层优先处理自己的手势。

聊天竖向滚动不触发页面历史；返回／前进不清空会话，不产生新工具调用。待确认动作仍由任务状态管理，不因滑动静默执行或丢弃。

所有关键能力也有按钮入口；VoiceOver 可读出页名、按钮、状态和重要字段。支持较大字体、减少动态效果和键盘操作；状态不能只用颜色表示。

## 10. 原生组件映射

| 设计组件 | 建议实现 | 需要注意 |
|---|---|---|
| 一级导航 | 已有路由／TabView 或 UIKit 容器 | 保留页面状态，不重建播放实例 |
| 历史返回与前进 | NavigationHistory 协调器 | 与既有导航结构和系统手势协调 |
| 消息与任务卡 | SwiftUI 自定义 View／UIKit 单元 | 状态来自统一任务模型 |
| 操作确认 | sheet／原生 presentation | 参数编辑后重新绑定确认 |
| 音乐主播放器与迷你播放器 | 共享 PlaybackCoordinator | 播放状态真实、同一个队列 |
| 授权列表 | List／分组表格 | 权限独立，系统弹窗按需 |
| 角色状态 | 既有资源／简单动画视图 | 不阻塞输入，不强制复杂 3D |

## 11. 执行者交付顺序

1. 推荐以潮汐为首版方向，提交首页及音乐页视觉细化；需要改方向时沿用航线备选。
2. 保留本轮布局预览供讨论，用香蕉生成真实参考图时记录模型、任务、提示词和版本。
3. 先统一基础颜色、字体、间距和按钮点击区，再实现五个页面／状态。
4. 修复第一阶段评审的上下文、权限、操作身份和摘要状态问题，不能仅改外观。
5. 接入共享迷你播放器和页面历史，验证左右滑动与键盘／滚动冲突。
6. 对照真机、深色、小屏、大字体、VoiceOver 和真实工具结果验收。

本轮产出是设计提案和交互预览；没有修改 http://127.0.0.1:8088/ 的演示功能代码，也没有完成真实音乐／系统操作接入。

06

六处关键偏差：哪些是合理重排，哪些必须补

偏差本身不等于错误；问题在于偏差之后有没有补验收、有没有同步产品口径。
D1

开发顺序：演示 / 模型先行，原生后补

顺序
原计划
先原生工具可靠，再接真实模型；M1 合流后先真机验证再扩功能。
实际
bb0fa75 先做 HTML 模拟 + 契约 + 后端；DeepSeek 流式早于 EventKit 真机验证；业务 UI 在 M2 后才补。
影响
早期无法验证系统写入；0.1.0 仅一条证据，0.2.x 又回到未验收状态。
判定：可接受的重排，但必须用真机验收把顺序债补回来。
D2

语音：讯飞方案替换为系统 Speech

方案
原计划
W01-021 复用讯飞 ASR / TTS，补齐最终听写、播报、打断与音频会话。
实际
使用 Speech + AVAudioEngine（zh-CN）；0.2.1 修复麦克风与语音识别权限，新增键盘收起。
影响
输入体验可用，但讯飞产品、凭据、播报与打断链路均未落地。
判定：需产品负责人确认替代方案；未确认前不能标“讯飞已接入”。
D3

UI：整批视觉方案废弃

范围
原计划
UI-02～UI-05 依赖丹青约香蕉稿，按选定方案还原与细化。
实际
《13_UI方案废弃决定》生效；旧演示关闭，原生直接实现四 Tab 业务界面。
影响
避免继续在旧稿上返工；但新视觉方向尚未明确。
判定：已按负责人决定执行，不计为开发失败；后续需新设计授权。
D4

免费签名：天气 / 运动能力不可用

边界
原计划
WeatherKit 与 HealthKit 全能力接入，按真实数据验收。
实际
免费签名 target 不申请受限能力；get_weather / get_activity_summary 返回 unavailable_in_free_build。
影响
W01-011 / 014 在免费版无法按原口径验收，必须另测正式签名构建。
判定：能力边界要在产品说明中明示，不能把“不可用”说成“已支持”。
D5

真机验收：被留到最后且尚未开始

风险
原计划
M1 演示四条路径，M2 过 P0 门槛，M4 执行 39 条矩阵。
实际
功能一路写到 M2，0.2.x 未执行任何正式用例；仅 0.1.0 有 1 条提醒写入。
影响
M1 / M2 不能判定完成；权限、时区、幂等与恢复缺陷可能集中暴露。
判定：最高优先级补课，先做提醒闭环与语音 / 键盘回归。
D6

计划外：AltStore / SideStore 与设备工具链

新增
原计划
未包含免费签名安装、HID 自动化与固定 IPA 落地脚本。
实际
新增 SideStore 路线、phone_hid.py、serve-ipa.mjs、publish-ipa.ps1。
影响
提升真机安装与分发效率，但不计入产品功能完成度。
判定：保留为交付支撑；汇报时与产品进度分开统计。
